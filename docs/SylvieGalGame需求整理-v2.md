# SylvieGalGame 需求整理-v2

> 二期规划稿。一期已完成「能玩」的竖切闭环（4 个场景、2 条分支、2 个结局），本稿不再重复一期范围，而是基于当前代码的真实能力，列出二期要补的体验、数据安全与工程能力。

**前提不变**：无剧本编辑器、纯 YAML 驱动、玩家端 only、React + Electron 交付、Web 预览壳辅助调试；剧情与素材仍只放在 `packages/game-content/game/`，不引入服务端与账号体系。

## 一、一期基线

| 模块 | 当前实际能力 | 二期要解决的问题 |
| --- | --- | --- |
| 指令 | 13 条：`bg` / `sprite` / `cg` / `text` / `bgm` / `se` / `voice` / `label` / `jump` / `choice` / `set` / `if` / `wait` | 演出表达偏少，文本不能引用变量，`set` 只能写字面量 |
| 转场 | 仅 `fade` / `none` | 缺少溶解、滑动、闪白、震屏等常用演出 |
| 文本 | 打字机、Auto、仅跳过已读的 Skip、Backlog、语音回放 | 无回滚、无数值插值；已读 ID 为 `block#index`，插入行会导致已读错位 |
| 音频 | BGM 单轨、SE 可叠加、VO 单实例打断；音量分组 | 存档只记 BGM 文件名，不记播放位置；无语音结束自动推进 |
| 存档 | 20 手动槽 + `save:auto` + `save:quick`；版本固定为 1；含截图、Backlog、章节、已读 | 无版本迁移；备注不可编辑；无导入导出；「继续游戏」只读自动存档 |
| 存档性能 | 每个 checkpoint（每条文本/选项）延迟 900ms 自动存档，并抓取截图 | 高频截图成本高，自动存档应更轻 |
| 平台 | Electron 自定义协议、JSON 存储、CSP、截图、全屏；Web fetch + localStorage + JPEG 缩略图 | Web 5MB 配额、移动端、离线能力未完善 |
| 内容 | manifest 仅 `title/version/start/scenes/variables` | 无章节名、标题背景、CG/音乐/结局图鉴等展示配置 |
| 工程 | 11 个 engine-core 单测、lint/typecheck、validate、桌面 CDP 冒烟、Docker | 无 CI、无 player 测试、无错误边界、无脚本 Schema、无日志 |

## 二、优先级定义

- **P0**：直接影响核心体验或存档安全，建议二期第一批完成。
- **P1**：显著提升体验或维护性，适合放在二期主体迭代。
- **P2**：锦上添花，视内容量和精力取舍。
- 工作量参考：**S**（约半天到 1 天）、**M**（2–4 天）、**L**（5 天以上，含测试与联调）。

## 三、引擎与剧本能力

1. **E1 文本回滚（P0 / M）**
   - 现状：引擎只能向前推进，读错选项或错过台词只能读档。
   - 需求：支持回到上一句 / 上一选择；滚轮上翻或 `PageUp` 触发，菜单提供「回到上一句」；回滚范围至少覆盖当前会话最近 30–50 个阻塞点，遇到选择时明确回滚到选择前状态。
   - 做法：引擎保存阻塞态快照环（指针、变量、舞台、BGM、Backlog 截断）并重放场景/BGM 效果；不依赖重新执行整段脚本。
   - 验收：跨 `label`、跨场景、选项前后均可回滚；回滚后继续推进不会重复 Backlog；回滚不写入已读标记。

2. **E2 文本变量插值（P0 / S）**
   - 现状：`text` 只输出字面量，数值变化只能写死在台词里。
   - 需求：支持 `{affection}` 一类占位符，可扩展 `{name}` 等角色变量；提供转义写法（如 `{{`）避免误替换；加载期校验未定义变量并给出警告。
   - 验收：数值 / 布尔 / 字符串均可插入；未定义变量在 `pnpm validate` 阶段报出；台词含花括号时可用转义输出。

3. **E3 已读标记稳定化（P1 / S）**
   - 现状：`text.id = block#index`，在场景中间插入或删除一条文本，后续已读标记全部错位。
   - 需求：改为「场景 + block + 文本内容哈希」或显式 `id` 字段；允许作者通过 `id` 固定关键台词。
   - 验收：调整无关台词后，已有 Skip 记录仍能命中未改动文本；重复文本可用显式 `id` 区分。

4. **E4 `set` 表达式与选项内动作（P1 / M）**
   - 现状：`set.value` 仅支持数字 / 布尔 / 字符串字面量，`+=` / `-=` 也只能加数字；选项只能跳转。
   - 需求：新增 `expr` 写法复用现有表达式解析器；`choice` 选项支持一个可选的 `set` 列表，选中后先执行再跳转；支持字符串拼接。
   - 验收：`set: { var: affection, expr: "affection + 1" }` 可用；选项内加好感后跳转结果可被后续 `if` 读到。

5. **E5 演出指令（P1 / M）**
   - 现状：只能靠 `bg` / `sprite` / `cg` 的淡入淡出。
   - 需求：新增 `shake`（震屏）、`flash`（闪白/闪黑）、`sprite` 的移动 / 缩放 / 翻转 / 层级控制；转场扩展 `dissolve`、`slide-left/right`、`wipe`，并允许逐条指定时长与缓动。
   - 验收：指令可组合、可被回滚快照正确恢复；未知参数有校验警告；不引入第二套动画库。

6. **E6 子程序与调用栈（P2 / L）**
   - 现状：公共桥段只能复制粘贴，或依赖跨场景跳转。
   - 需求：`call` / `return` 支持调用 label 并返回；调用栈写入存档与回滚快照。
   - 验收：嵌套调用、跨场景调用、存档恢复调用栈均正确。

7. **E7 章节与结局元数据（P1 / S）**
   - 现状：章节名直接取最近一次 `label`，结局没有注册表。
   - 需求：manifest 增加 `chapters`（label → 展示名）、`endings`（id / 标题 / 描述）；引擎在 `ended` 前发出结局 id，供图鉴与存档备注使用。
   - 验收：存档面板显示可读章节名；结局图鉴可依据已达成记录点亮。

8. **E8 错误与校验体系（P0 / M）**
   - 现状：初始化失败只有一个全屏提示；脚本问题只进控制台；警告不带文件行号。
   - 需求：运行期收集警告并在 UI 提供可展开的错误面板；`pnpm validate` 输出 `scene.yaml:行号` 与错误级别；区分「错误（阻断启动）」与「警告（可继续）」。
   - 验收：故意写坏一个跳转/资源路径，能在启动前定位到文件和行；播放器提供「复制诊断信息」。

## 四、表现与舞台

1. **S1 UI 隐藏模式（P1 / S）**：一键隐藏对话框、快捷栏与光标（右键或 `H`），再点任意处恢复；截图存档不受影响。
2. **S2 舞台缩放与安全区（P1 / M）**：立绘支持 `scale` 与 `z`，避免多角色遮挡只能靠 id 顺序；不同分辨率下保持底部对齐。
3. **S3 图鉴与回放（P1 / M）**：标题页新增 CG 鉴赏、音乐鉴赏、结局列表；解锁标记独立存 `meta:gallery`，与存档解耦。
4. **S4 标题页配置化（P1 / S）**：manifest 支持标题背景、标题 BGM、副标题与版本展示文案，替换内容包即可换皮。
5. **S5 文本框主题（P2 / M）**：背景透明度、字体大小、文本框位置作为设置项或内容配置；至少提供「不透明 / 半透明」两档。
6. **S6 无障碍与动态效果（P2 / S）**：尊重 `prefers-reduced-motion`，减少转场；对话用 `aria-live` 已有基础，补齐焦点陷阱与键盘选中选项。

## 五、文本与交互

1. **T1 回滚入口与提示（P0，依赖 E1）**：对话区提供「上一步」按钮，滚轮上翻触发；回滚后给出轻提示，避免误操作。
2. **T2 选项键盘操作（P1 / S）**：选项出现时默认聚焦第一项，支持方向键 / 数字键 / 回车；当前只能鼠标或 Tab。
3. **T3 跳过策略（P1 / S）**：设置增加「仅跳过已读 / 跳过全部」；跳过全部需二次确认；跳过时可选静音 SE / VO。
4. **T4 语音感知的 Auto（P1 / S）**：有语音时按语音结束推进，无语音时按固定等待；当前只按 `autoDelay`。
5. **T5 Backlog 增强（P2 / M）**：支持搜索、按角色筛选、跳回某句（需 E1），可导出当前会话文本。
6. **T6 统一确认弹窗（P0 / S）**：替换 `window.confirm`（覆盖存档、删除、返回标题），改为应用内 Modal，避免阻塞、样式割裂和自动化测试卡死。

## 六、音频

1. **A1 BGM 位置持久化（P1 / S）**：存档记录 `bgmPosition`，读档后 `seek` 恢复；当前每次读档从头播放。
2. **A2 音频通道扩展（P2 / M）**：保留 BGM 单轨，增加环境音/循环 SE 通道；明确打断规则。
3. **A3 预加载预算（P1 / M）**：当前进入场景会预加载该场景引用到的全部图片与音频，且音频预加载表不回收；改为「当前场景 + 下一跳候选」并设数量/体积上限，超限按需加载。
4. **A4 资源格式与响度（P2 / S）**：正式素材统一 WebP / OGG（保留 MP3 回退），BGM 做响度归一；占位资源仍由脚本生成。

## 七、存档与系统

1. **V1 存档版本迁移（P0 / M）**
   - 现状：`isSaveData` 要求 `version === 1`，直接加字段会让旧档全部读不出来。
   - 需求：升级到版本 2 起，按版本逐级迁移；迁移失败给出明确提示；未知新字段不丢。
   - 验收：用一期生成的自动/手动存档升级后能读；迁移过程幂等。

2. **V2 内容指纹校验（P1 / S）**：存档记录内容 `version` 或关键脚本哈希；内容已替换时提示「存档可能不兼容」，但不阻止读取。

3. **V3 存档备注与导入导出（P1 / M）**：保存时允许编辑备注；桌面端通过系统对话框导出/导入单档与全量 JSON；Web 端通过下载/上传文件实现，直接解决 localStorage 配额与迁移问题。

4. **V4 自动存档轮换（P1 / S）**：`save:auto` 扩展为 2–3 个轮换槽，避免一次误操作覆盖唯一进度；「继续游戏」读取三类存档中最新的一份，而不是只看自动存档。

5. **V5 自动存档减负（P0 / S）**：自动存档不再每条文本都抓截图，改为「章节/选项节点抓图 + 普通节点仅存状态」；手动存档仍保留缩略图。当前每条文本都可能触发 `capturePage`。

6. **V6 Web 存储升级（P1 / M）**：`KeyValueStorage` 增加 IndexedDB 适配并请求 `navigator.storage.persist()`；localStorage 保留为回退。存档量增长后比 5MB 配额更稳。

7. **V7 存档安全与清理（P1 / S）**：损坏存档单独提示而不是静默忽略；提供「清理全部存档」「按时间排序」；桌面端退出前写一次自动存档。

## 八、UI 与体验

1. **U1 错误边界与日志（P1 / S）**：React `ErrorBoundary` 兜底白屏；提示存档/日志路径；桌面端把运行日志写入 `userData/logs`。
2. **U2 设置增强（P1 / M）**：新增跳过策略、文本框透明度、UI 缩放、截图开关、重置设置；音量滑动时可试听。
3. **U3 载入进度（P2 / M）**：初始化显示「脚本解析 → 资源校验」阶段与进度，长内容包不再只显示静止提示。
4. **U4 菜单信息（P2 / S）**：菜单显示当前章节、游玩时长与最近存档时间；返回标题前提供「先存档再退出」。
5. **U5 Web 移动端适配（P2 / M）**：触屏点击推进、滑动打开 Backlog、安全区适配；当前快捷栏与存档面板以桌面鼠标操作为主。
6. **U6 启动与窗口状态（P1 / S）**：Electron 记录窗口大小/位置，增加单实例锁；全屏恢复失败时静默回退。
7. **U7 键位说明（P2 / S）**：应用内帮助页列出快捷键，设置面板不再挤在底部小字里。

## 九、内容与工具链

1. **C1 manifest 扩展（P1 / S）**：增加 `windowTitle`、`title` 展示配置、章节表、结局表、图鉴资源表；所有字段保持可选，旧 manifest 不需改动。
2. **C2 YAML Schema（P1 / M）**：提供 `docs/script.schema.json`，让 VSCode YAML 插件补全与内联报错；`pnpm validate` 与 Schema 共用同一份约束。
3. **C3 内容体检（P1 / M）**：检查未引用资源、重复 label、不可达场景、缺失语音、超大图片/音频、资源命名规范；输出可读报告。
4. **C4 素材流水线（P2 / M）**：`pnpm assets` 增加正式素材优化（图片转 WebP、音频转 OGG、生成校验清单）；占位素材生成逻辑保留。
5. **C5 示例内容扩充（P1 / 内容量决定）**：二期至少新增 1 条完整路线与 1 个结局，用于验证图鉴、章节和回滚；剧本格式文档同步更新。

## 十、工程、测试与交付

1. **Q1 CI（P1 / M）**：GitHub Actions 增加 lint、typecheck、test、validate、Web build；Windows job 可选 package/smoke。当前仓库没有 `.github` 配置。
2. **Q2 测试补齐（P1 / M）**：引擎补指令、表达式、存档迁移、回滚、已读稳定 ID 用例；player 增加设置/存读档状态测试；当前 11 个用例集中在 engine-core。
3. **Q3 Web 冒烟自动化（P1 / S）**：把现有 `scripts/.smoke/check-web.mjs` 整理为可提交脚本（截图目录仍忽略），CI 中用无头 Chrome 跑标题 → 分支 → 存读档。
4. **Q4 Web 构建优化（P1 / S）**：对存档、设置、图鉴等面板按需加载，拆分 `html-to-image`，消除单 chunk 500kB 警告。
5. **Q5 桌面交付（P1 / M）**：自动更新（可选）、安装包签名的准备工作、版本号统一从 manifest / package 注入；当前 NSIS 未签名。
6. **Q6 Docker 内容热替换（P1 / S）**：Compose 支持把 `packages/game-content/game` 以只读卷挂到 `/usr/share/nginx/html/game`，改剧情不必重建镜像；默认仍保留内置内容。
7. **Q7 发布流程（P2 / M）**：语义化版本、CHANGELOG、Release 附件（免安装包与 Web 镜像）；提交仍直接在 `main`，不新建特性分支。

## 十一、性能与稳定性

1. **P1 快照开销（P2 / S）**：`emit()` 每次都复制完整 Backlog；改为只读引用或分页，长会话下减少分配。
2. **P2 音频解码（P2 / S）**：BGM 使用流式播放，避免整轨解码常驻内存；SE 仍走短音缓存。
3. **P3 资源缓存（P1 / M）**：图片与音频预加载增加 LRU 与体积预算，避免内容量上去后内存持续增长。
4. **P4 存档写入节流（P1 / S）**：自动存档、设置写入合并为串行队列；Web 端捕获配额错误并提示导出。

## 十二、二期限定不做

- 不做剧本编辑器、在线协作、账号与云存档服务。
- 不引入 Live2D / 视频背景 / 3D；舞台仍是背景 + 立绘 + CG 的静态图层。
- 不做资源加密与强混淆；二期仍以松散资源、可替换内容包为前提。
- 不做 macOS / Linux 正式交付；桌面端继续以 Windows 为首要目标。
- 不做多语言 UI；若未来有需求，再单独抽文案层。

## 十四、验收总则

二期完成时至少满足：
